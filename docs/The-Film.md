# The film

`demo/film.mp4` is 90 seconds in four chapters, made for engineers and project managers who have ninety seconds.

1. **What it does** (0 to 17 s): a terminal prompt runs the project's real first command and the response becomes a printed object. Altar. One hundred percent. Then the stake: Column has 1,631 photos. Apse has 437. Can it learn the rare ones?
2. **How it is built** (17 to 40 s): a paper model of the pipeline, stage by stage, with the race: Chance 10.0%, Notebook VGG16 (validated on test) 90.0%, MobileNetV2 quick, 15% of data 89.3%, MobileNetV2 full 93.3%; MobileNetV2 full wins, the one line of code that matters, the API call and the tests.
3. **The proof** (40 to 68 s): the real app, recorded. Altar: one click, top-3 bars Apse, bell tower: same model Curves and per-class: apse is 61%
4. **The answer** (68 to 90 s): 93.3%, test accuracy · 1,473 photos never seen in training. Notebook 90.0 → 93.3 here. And it ships. One limit: Apse: 61%. It looks like a tower from outside. Then the prompt types `just setup && just up`.

`demo/film-60s.mp4` is the same without the proof chapter. `demo/demo.mp4` is the plain captioned walkthrough of the app.

Every number in the film comes from the project's own metrics, findings or a live response; nothing is drawn by hand. The film pipeline lives in the author's workspace, not in this repo.
